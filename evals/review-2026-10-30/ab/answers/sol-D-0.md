### Q1
`uv run dg check yaml --validate-requirements` fails if `API_TOKEN` is not declared in the component’s `requirements.env`; this checks declared requirements, not whether the variable exists in the environment. `uv run dg check defs` passes for otherwise valid definitions because it does not enable that requirements check, and missing `env.API_TOKEN` resolves to `None`, producing the literal asset description `"token=None"`. Use `{{ env('API_TOKEN') }}` if missing environment variables should raise during resolution instead of silently entering the description ([1.13.28 implementation](https://github.com/dagster-io/dagster/blob/1.13.28/python_modules/dagster/dagster/components/resolved/scopes.py#L10-L35)).

### Q5
You must refresh the project’s installed entry-point metadata, but `uv pip install -e .` is unnecessary if `uv sync` already builds and reinstalls the project. Once the project declares a `dagster_dg_cli.registry_modules` entry point, Dagster 1.13.28 ignores `[tool.dg.project].registry_modules`, so remove that redundant list rather than expecting it to supplement the entry point. The entry-point module must export the intended component classes ([discovery implementation](https://github.com/dagster-io/dagster/blob/1.13.28/python_modules/libraries/dagster-dg-core/dagster_dg_core/component.py#L30-L76)).

### Q10
`BackfillPolicy.single_run()` executes once for the entire selected range, so `context.partition_key` raises `DagsterInvariantViolationError` when that range contains multiple days. Process every selected day using `context.partition_time_window`, `context.partition_key_range`, or `context.partition_keys` instead. Returning a combined DataFrame also requires a range-aware IO manager, because the default filesystem IO manager cannot persist one output associated with multiple partitions; alternatively, write the range directly to storage with an asset annotated `-> None`. If the computation must remain single-day, use `BackfillPolicy.multi_run(max_partitions_per_run=1)` ([backfill guidance](https://docs.dagster.io/guides/build/partitions-and-backfills/backfilling-data#launching-single-run-backfills-using-backfill-policies)).

### Q19
In 1.13.28, enter `with dg.partition_loading_context(effective_dt=context.scheduled_execution_time):` and call `key = daily_partitions.get_last_partition_key()` inside that block, then return `dg.RunRequest(partition_key=key)`. If `key is None`, return `dg.SkipReason(...)` instead. Do not pass `current_time=` or `scheduled_execution_time=` to `get_last_partition_key()`, whose signature takes no arguments in this version ([partition-loading context](https://github.com/dagster-io/dagster/blob/1.13.28/python_modules/dagster/dagster/_core/definitions/partitions/context.py#L87-L115)).

### Q23
Default `dg.AutomationCondition.eager()` considers only the latest daily partition, so it requests at most one of those 30, not all 30; merely enabling it on already-missing history produces zero requests initially. To permit automation for older partitions, remove the latest-window restriction with `.without(dg.AutomationCondition.in_latest_time_window())`. To include already-missing history rather than only subsequent triggering changes, also use `.replace(dg.AutomationCondition.newly_missing(), dg.AutomationCondition.missing())`, subject to eager’s remaining dependency and in-progress guards, or launch an explicit backfill ([1.13.28 eager definition](https://github.com/dagster-io/dagster/blob/1.13.28/python_modules/dagster/dagster/_core/definitions/declarative_automation/automation_condition.py#L926-L945)).

### Q32
Subclass `dg.ConfigurableResource`, declare the config field, and override `create_resource(self, context: dg.InitResourceContext) -> GitHub` to return `GitHub(self.token)`. Annotate the asset parameter as `github: dg.ResourceParam[GitHub]`, and register the resource instance under the matching `"github"` key in `dg.Definitions(resources=...)`. Dagster 1.13.28 does not export `dg.ConfigurableResourceFactory` or `dg.Resource[T]`; the supported names are `ConfigurableResource` and `ResourceParam[T]` ([resource documentation](https://docs.dagster.io/api/dagster/resources)).

### Q36
The external Pipes call accepts and transmits that metadata envelope, but Dagster’s receiving-side conversion rejects the list-valued schema with `ParameterCheckError`. For `"type": "table_schema"`, use `"raw_value": {"columns": [{"name": "id", "type": "int"}]}`, not a bare column list ([receiving-side conversion](https://github.com/dagster-io/dagster/blob/1.13.28/python_modules/dagster/dagster/_core/definitions/metadata/external_metadata.py#L109-L126)).

### Q44
On a fresh macOS/Linux installation, 1.13.28 writes `~/.config/dg.toml` under `[cli.plus]`; `XDG_CONFIG_HOME` changes the directory, and `DG_CLI_CONFIG` overrides the complete path. If `~/.dagster_cloud_cli/config` already exists, the CLI reuses that legacy file instead. If both files contain Plus configuration, loading or writing raises `"Found Dagster Plus config in both ... Please consolidate your config files"` rather than applying precedence, so consolidate the Plus settings into one location ([config selection and writing](https://github.com/dagster-io/dagster/blob/1.13.28/python_modules/libraries/dagster-shared/dagster_shared/plus/config.py)).

### Q50
A common cause in converted legacy projects is a missing `[build-system]`: `uv sync` installs dependencies but does not install the project itself, leaving its new entry point absent from installed distribution metadata. Declaring the entry point also disables Dagster’s old `registry_modules` fallback, so adding the TOML table alone can make local components disappear. Add a suitable build backend and package-discovery configuration, ensure `[tool.uv].package = false` is not disabling installation, and rerun `uv sync`, or explicitly install with `uv pip install -e .` ([uv packaging rules](https://docs.astral.sh/uv/concepts/projects/config/#build-systems)). Point the entry point at an importable module that exports your component classes, then check `uv run dg list registry-modules` and `uv run dg list components`.

### Q55
In dagster-dbt 0.29.28, `DbtCliResource` defaults to `"dbtf"` if `shutil.which("dbtf")` finds it, otherwise `"dbt"`; set `dbt_executable=` to override that choice ([executable selection](https://github.com/dagster-io/dagster/blob/1.13.28/python_modules/libraries/dagster-dbt/dagster_dbt/core/resource.py)). For a Fusion invocation, `.stream().fetch_row_counts()` logs a warning and passes the events through without adding row-count metadata, because Fusion does not provide the dbt Core adapter used to fetch counts; it does not raise an unsupported-feature exception ([iterator implementation](https://github.com/dagster-io/dagster/blob/1.13.28/python_modules/libraries/dagster-dbt/dagster_dbt/core/dbt_event_iterator.py)).
